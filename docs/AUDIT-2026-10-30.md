# Auditoría del MVP — 30 octubre 2026

Base: rama `feat/instant-web-builder-mvp`, PR #1, commit `bfcb8ef`.

## Arquitectura y material existente

El repositorio contiene principios, un diario de investigación y tres HTML de ejemplo; la aplicación es independiente en `builder/`: Next.js App Router, una página cliente, layout y un generador determinista. No había servidor de generación, persistencia, IA, historial, autenticación ni publicación. Se conservan los ejemplos como material histórico y se reutilizan Next.js, React, el formulario y la exportación segura de texto.

Se leyeron `prompts/bot.md`, biblioteca, diario y principios. El contrato y la biblioteca prevalecen sobre patrones antiguos. `examples/restaurants/README.md`, los heroes, botones, sticky CTA y el flujo de una hora seguían recomendando plantillas contrarias al contrato: deben señalarse como históricos y corregirse antes de reutilizarlos. Las siete entradas del PR añaden archivos distintos bajo el mismo mensaje; no son siete implementaciones duplicadas.

## Hallazgos y correcciones de base

- No había lockfile ni `.gitignore`: se fijan las versiones de ejecución y se excluyen dependencias, builds y secretos.
- PostCSS vulnerable: override 8.5.32 compatible con la rama Next 15.5.28. No se fuerza una migración de framework. La instalación posterior informa **0 vulnerabilidades**.
- El meta description se truncaba después de escapar y podía cortar entidades. Ahora se limita texto antes de escapar.
- Contacto vacío generaba un botón que enlazaba a sí mismo: no se ofrece un contacto directo inexistente.
- Se añaden ESLint con reglas oficiales Next, TypeScript y pruebas reproducibles de inyección, metadatos y contactos. La primera pasada de lint detectó tres escapes innecesarios; se corrigieron.
- Los estilos del MVP cambiaban colores y fuente pero no estructura; queda documentado para el motor visual de la fase siguiente.
- El iframe ya tenía `sandbox=""`: se conserva el aislamiento. El motor no debe aceptar HTML ni JavaScript arbitrarios del modelo.

Vercel: Root Directory `builder`, Node >=22. No hay despliegue ni fusión autorizados en esta auditoría. Las verificaciones finales, tiempos y límites del producto ampliado se registran en `docs/VERIFICATION.md`.
